01 / BRIEF明确结构与验收标准

先把界面拆成主页面、次级页面和状态，不要把“更精致一点”当成可执行需求。这里明确：研究是默认游戏页；底部导航只有研究、文明、群星；游戏内有任务、档案、帮助、视图；外部补给和设置在最上方；主要操作为撤回、连接、末端、跳过。

输入
截图 + 功能描述 + 用户评审
交付
DESIGN_BRIEF.md + 页面导航表 + QA 条件

02 / IMAGEGEN用 ChatGPT 生图进行艺术指导

先生成完整页面的高保真概念，锁定材质、光效、色彩和信息密度；同系列页面沿用同一风格锚点。该阶段产物应当被标为“视觉参考”，不是最终可交互界面。

尽量另外生成“无文字、无按钮、无节点标记”的干净场景背景，比直接从完整 UI 截取会更容易复用。本案例验证了从现有概念图拆图的方案，但还保留部分烧录在位图里的神经连线，不能直接作为正式科研数据。

03 / ASSETS裁切、蒙版和 WebP 资源

把概念图中可复用的背景、头像、徽章和档案缩略图提取出来，记录源文件、裁切坐标和蒙版形式。Pillow 提供 Crop、Alpha、GaussianBlur 和 WebP 输出；在项目中用 manifest.json 保存来源。

python -m pip install pillow numpy
python tools/build_assets.py
# 输出 assets/*.webp 与 assets/manifest.json
设计边界
美术图像 ≠ 实际节点数据；交互位置仍由 DOM / Canvas / 3D 引擎控制

04 / WEB PROTOTYPE将视觉素材合成可操作网页

图像作为美术资产进入页面，使用 <img>、CSS background 和透明叠层；按钮、文字、计分、进度条、页面切换必须是可操作元素。本案例无数据库也能展示真实的页面状态变化。

# 进入工程根目录
python -m http.server 8000
# 然后用浏览器打开 http://127.0.0.1:8000

动态网页有不同层次：CSS 动画是视觉动效，JavaScript 是浏览器状态交互，WebSocket / API / 数据库用于真实多人数据与服务端功能。本次只需要前两层，**不必为了发光按钮和状态更新而引入后端**。

04B / 3D GEOMETRY & ENDPOINTS三维神经骨架与端点一致性

V1.3 增加了真正的 XYZ 纤维控制点与透视相机。用户可以拖动旋转、滚轮或双指缩放、双指平移，并通过视图工具切换正面/侧面/俯视。可点击端点不再来自 CSS 的固定 left/top，而是直接绑定到三维骨架段的首末顶点，再随相机投影到屏幕。

新增源码
scene3d.js · docs/DATA_ADAPTER_SPEC.md · tests/verify_v12.py
此处展示**三维合成骨架模型**，并非真实两光子或电子显微神经数据。需要真正科学准确的端点，必须接入原始骨架、node ID、体素到物理坐标变换，而不能凭生成的图猜测。

游戏内「？」提供当前片段前置知识与操作提示；设置中的「通用玩法与应用帮助」只介绍普适操作和游戏背景。这两种帮助与任务状态分别管理。

04C / MULTI-TASK GRAPH EDITOR多任务骨架与可编辑连接

V1.3 不是把两个固定端点的连线复制五次，而是五种几何不同的合成任务：主干断点、分叉重建、投影交叉歧义、低信噪比、高密度末梢。每个候选端点是其所引用骨架线段的首末 XYZ 顶点。

核心数据契约
task: { id, name, condition, segments[], candidates[] }
segment: { id, p: [[x,y,z], ...] }
endpoint: "segmentId:start" | "segmentId:end"
addedEdge: { id, taskId, from, to, kind: "user-created", createdAt }

依次点击两个端点，连接后生成独立用户连边；点击连边选中，再点击删除。撤回保留最近编辑的快照。任务切换后仍保留各任务的连边；刷新页面通过 localStorage 恢复模拟数据，且不会同步到其他设备。

镜头与视觉
旋转：鼠标或单指拖动
缩放：滚轮或双指捏合
平移：Shift+拖动 / 双指平移
镜头重置：正面 / 侧面 / 俯视（三种完整预设）
配色：青蓝 / 紫蓝 / 高对比 / 薄荷 / 琥珀
对比度：55%—155%
演示中的成像条件只影响合成画面表现，不能等同真实显微光学退化模型；连边的点击命中测试是 3D 线段投影到屏幕后的 2D 距离，正式项目需校验遮挡、深度和 Raycast 逻辑。

05 / PLAYWRIGHT怎样自动看效果、发现遮挡？

Playwright 是浏览器自动化测试工具。它启动 Chromium，像真实用户一样打开网页、点击按钮、读取状态、截取截图。它并不设计图片，也不判断“是否高级”，而是对已确定的设计做工程一致性检查。

python -m pip install playwright
python -m playwright install chromium
python tests/verify_v12.py --base-url http://127.0.0.1:8000

测试文件会检查底部导航和操作栏是否相互遮挡、图片是否成功加载、端点选择后按钮状态是否改变、连线是否增加任务进度、档案与排行榜能否正常切换，以及手机教程抽屉能否打开。

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page(viewport={"width": 390, "height": 844})
    page.goto("http://127.0.0.1:8000")
    # 使用 3D 视图的投影端点坐标进行点击
    ends = page.evaluate('window.__neural3dViewer.projectedEndpoints()')
    canvas = page.locator('.nerve-canvas')
    # 实际测试脚本还处理页面缩放与坐标转换，见 tests/verify_v12.py
    assert page.locator("#connect").is_enabled()
    page.locator("#phone").screenshot(path="game.png", animations="disabled")
    browser.close()

为什么截图时设置 animations="disabled"？因为动态闪烁和粒子位置每帧都变化，不固定画面会造成大量无意义的视觉差异。正式审核时应同时保留真实动画预览。Playwright 官方截图文档 ↗

06 / VERCEL部署成每个合作者都能访问的网页

本项目是纯静态托管的浏览器交互前端，Vercel 保存网页和 WebP 资源并提供 HTTPS 域名，无需数据库。在具备授权的连接下，可通过 Vercel API 发布；也可本机安装 CLI 后发布，或长期绑定 GitHub 仓库自动生成 Preview 链接。

# 可选：在已登录 Vercel CLI 的电脑中
npm i -g vercel
vercel deploy            # 获取审稿 Preview URL
vercel deploy --prod     # 审核通过后生产发布
Preview 的访问保护取决于项目配置，生产网址也需验证权限。用公开链接共享前，先确认素材与数据已获授权。本项目展示的神经影像及榜单内容均为示例。

V1.3 · 概念图驱动 UI 资产复现

概念美术参考：原始研究、榜单、回声档案三张图。根据截图提取可复用图像素材，再用 CSS 与可操作组件重建荣誉台、排名称号、档案统计和积分装饰。

交互修正：末端工具先选择原始三维骨架线段，然后仅显示该段的 S / E 端点；玩家创建的连边仍独立选中、删除。影像风格与建模风格共享合成骨架，前者是示意渲染，并非真实显微影像。

验证流程：Playwright 测试双视口、原始线段拾取、显示模式切换、档案搜索与排行榜；随后提交 GitHub 并部署 Vercel。
