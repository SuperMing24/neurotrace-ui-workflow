# 资产保管与许可登记

## 三类保管方式

| 类别 | 本项目中的内容 | 理由与规则 |
| --- | --- | --- |
| 纳入版本控制 | 可维护代码、CSS、接口、SQL 迁移、合成夹具、文档、测试、体积适中的 WebP／SVG、设计概念图、已有版本清单及历史字节 | 可以审查变化、恢复版本并追溯来源；有权利缺口的既有文件先保留证据，不视为已取得商用许可 |
| 外部受控保存 | 大尺寸原始摄影／原画、设计母版、原交付 ZIP、许可证明、私人服务模板、数据库备份与生产记录 | 公库只保存定位线索、SHA-256、版本、访问人和许可状态；本轮只有本机参照保管，尚未创建对象存储、上传或放宽权限 |
| 不进 Git | 密钥、数据库 URL、授权卡、Cookie、会话／设备哈希、私人信件、个人订单资料、真实影像与未授权数据；本地依赖、构建目录、重复截图、缓存 | 敏感信息由受控系统管理；可再生成内容用命令和摘要取代。`.gitignore` 只是保护新内容，不清除既有 Git 历史 |

## 原件与交付

不要把完整生产备份、授权卡或含私人模板的原包直接附到公共 Release。外部资源入库前先确认用途与授权，记录来源 URL／文件 ID、取得时间、原始哈希、派生工具及参数。已有公开版本不在本轮删除或替换；清理权限、下架或换音轨属于单独的线上变更。

原仓库未指定整个项目的 LICENSE，本轮不替负责人选开源协议；public 可见性不代替授权。详见 [第三方署名](../../THIRD_PARTY_NOTICES.md) 和 [缺口表](GAPS.md)。

本轮少量人工选择的桌面、手机及对照截图放 `docs/engineering/evidence/`，作为本轮审查证据保留；它们不是历史原画或许可证明。批量截图、浏览器追踪与完整构建继续排除出 Git。
