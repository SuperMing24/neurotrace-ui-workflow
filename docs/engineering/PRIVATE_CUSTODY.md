## 恢复方法

1. 从公开索引取得目标对象 key、SHA-256 和大小；使用已有获准的 Neon 管理连接请求该 bucket／分支的短期 download 签名。不要生成 public_read bucket、公共分享链接或长期密钥来恢复。
2. 使用 `tools/vault_transfer.py`，通过隐藏标准输入提交下载任务：`operation` 为 `download`，字段包括 `name`、`key`、`sha256`、`download`。外层指定新的 `downloadDirectory` 和本机 `receipt` 路径。签名地址只能进入隐藏输入，不能写入命令行、脚本或 Git。工具校验下载哈希并测试匿名拒绝。
3. 对已校验的私信包执行 `python -X utf8 tools/private_vault.py restore <本机已下载包> <全新恢复目录>`。工具校验内部清单，只写全新目录，不覆盖工作区或生产路径。
4. 核对恢复出的原服务文件／正文测试的哈希，再由负责人决定是否将本机覆盖用于开发。此步骤不授权部署、更新服务器模板或修改账号权限。独立 templates.json 是保管副本，目前不是生产运行时配置。

首次本机打包可执行 `python -X utf8 tools/private_vault.py pack <仓库之外的新目录>`。该工具不联网；只封装已有文件、提取现有模板并记录缺失母版，不生成美术。目录创建后应由当前用户与 SYSTEM 管理，不能放进公共仓库或静态服务根目录。

## 保留、分支和权限规则

此 bucket 依附现有 `preview-1-8` 分支。该分支从现在起也是保管锚点，不能按普通临时预览分支删除、重置或随意作为新分支的克隆基线。Neon 存储随分支继承，创建后代分支前要审查私有对象的继承与凭据访问范围。

删除／重置承载分支或迁移保管服务前，必须先将所有对象复制到已确认的另一私有位置，核对数量与哈希，实际恢复至少一份私信包和设计包，并更新索引后再批准清理。当前本机和云端均有校验副本；这不能代替长期独立备份、服务端对象锁或已验证的自动保留策略。

未来若要解除这个生命周期耦合，应迁到独立工程保管项目或其他独立私有存储；本轮没有创建／复制数据库分支，也没有调整分支保护、账号权限或生产资源。
